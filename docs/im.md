1. 目标与技术路线
目标是保留官方 SANDO 的数学模型、规划流程、动态环境处理和仿真入口，使用本人已取得的 AMPL 授权运行 Gurobi。
推荐结构：
```text
SANDO 原始轨迹公式与原始调度
        ↓
C++ 建模适配层：记录变量、表达式和约束
        ↓
真实的 AMPL 轨迹模型
        ↓
NL 文件：AMPL 编译后的模型
        ↓
AMPLS 的 C++ 接口
        ↓
AMPL 授权的 Gurobi
        ↓
原始变量数值、原始求解状态、原始轨迹提取
```
AMPLS 官方接口支持从 AMPL 模型载入求解器、使用 AMPL 授权，以及取得底层 Gurobi C 接口模型。[A1][A2] 普通 AMPL 命令行求解通过，证明的是这一入口可用；生产接入还需要验证匹配的 AMPLS 共享库、原生回调、并发实例和长期授权更新。
保留 `SolverGurobi`（原有求解器类）的调用接口。新增的适配层仅覆盖本项目使用的建模功能。取得 `getGRBmodel()`（底层模型指针）之后，使用官方 Gurobi C 接口。官方公开的 Gurobi C++ 模型构造函数采用环境或已有 C++ 模型作为输入；原有 C++ 对象与底层 C 指针之间仍需明确适配。[A2][G1]
整个 SANDO 问题通过真实 AMPL 模型进入求解器。授权初始化、求解和模型更新均遵守实际授权范围及官方接口。
2. 源码中必须保持的数学语义
2.1 轨迹与自由变量
每段位置为三次多项式：
`p(t) = a t³ + b t² + c t + d`。
位置、速度、加速度和加加速度的求值顺序，保留源码中的表达式。这里加加速度是“加速度的变化速度”。默认配置为五段、每层三个候选多面体；多面体就是由若干平面围出的凸区域。[S2][S3]
开启变量消元时，四段有三个连续自由变量，五段有六个，六段有九个。`d3`、`d4`、`d5`（源码中的自由位置参数）对应部分分段多项式的常数项。四段、五段、六段的系数计算与数值提取函数成对保留。[S2]
源码为这些自由位置参数设置有限上下界：水平地图边界外扩五米，高度边界外扩两米。适配层保留这些数值。[S2]
2.2 时间分配
每段时间保持：
`分段时间 = 时间系数 × max(初始估计时间, 2 × 采样间隔)`。
同一次优化中各段等时。默认采样间隔为 0.01 秒，默认单模型 Gurobi 求解时限为 1 秒。采样间隔描述轨迹采样，求解时限描述求解器工作时间。[S2][S3]
2.3 目标函数
保持源码实际目标：各段三维加加速度平方和之和，再乘权重。默认权重为 10。
原式逐段求和。保留源码的常数项、交叉项与数值计算顺序。二次表达式统一保存为 `常数 + 线性项 + Σ q_ij x_i x_j`，以此固定交叉项约定。[S2]
2.4 走廊约束
每段候选多面体的二元变量之和满足 `Σ z >= 1`。
对第 t 段、第 p 个候选区域、每个平面和每个位置控制点，保持：
`z[t,p] = 1 ⇒ A[t,p] × 控制点 <= b[t,p]`。
指示约束的意思是：二元开关取 1 时，相应限制生效。二元变量、触发值、方向、平面、控制点和常数项逐项保留。空多面体的对应二元变量固定为 0。[S2]
时间分层索引保持 `t × P + p`。不同时间层采用各自区域。[S2]
本提交实际添加的走廊和地图边界约束调用 `getCP0` 至 `getCP3`（贝塞尔位置控制点函数）。项目同时存在 MINVO（另一套轨迹控制点表示）相关函数。实施以真实调用链为准，分别保持两类函数的用途。[S2]
2.5 动力学约束
保留全部已有模式：
`Linf`（逐轴限幅）：各轴控制点分别满足上下限。
`L1`（各轴绝对值之和限幅）：保持源码的八种符号组合线性不等式。
`L2`（三维长度限幅）：保持原始二次约束。
默认模式形成混合整数二次规划。三维长度模式还带有二次约束。适配层应包含相应能力。[S2][S3]
3. 源码中必须保持的运行语义
3.1 求解调用链
保持 `generateNewTrajectory`（生成新轨迹）的顺序：
检查中止标志。
计算分段时间。
计算消元后的多项式系数；对原有完整变量模式，添加边界和连续性约束。
更新走廊约束。
更新动力学约束。
更新目标函数。
更新地图边界约束。
再次检查中止标志。
调用求解器。
按原有成功条件提取系数和时间信息。
3.2 成功判定
当前官方 `callOptimizer`（调用优化器）仅在原生状态 `GRB_OPTIMAL`（达到配置容差下的最优状态）时返回成功。超时、中止和其他状态均保留原有失败处理。[S2]
适配层返回原生状态码。目标值和变量值只在原有条件允许时交付给轨迹生成器。求解失败时，旧解与本次请求隔离。
3.3 并行时间搜索
`src/sando/sando.cpp`（规划器实现）为不同时间系数建立独立求解器，并分配各求解器的内部线程。默认参数通常形成九个时间系数候选，实际数量以运行时计算为准。[S3][S4]
每个候选工作单元独立拥有：AMPL 会话、AMPLS 模型、求解器上下文、临时目录、变量映射、结果和中止标志。保留现有候选顺序、线程数、成功结果选择和其余任务中止策略。
初始化允许串行完成。运行阶段保持原版的独立并发求解。实际授权是否支持所需并发规模，通过小测试证明。
3.4 中止与生命周期
`stopExecution`（请求停止）设置原子标志；求解中的回调读取标志并终止当前模型。`resetToNominalState`（清除停止状态）在上一任务退出后为下一次调用准备。[S2]
回调仅做中止检查等短操作。回调结束、求解线程退出和模型释放具有明确顺序。中止标志采用请求代次隔离，防止上轮结果进入下一轮规划。
源码的共享 Gurobi 环境初始化位于求解器头文件 `getSharedEnv`（取得共享环境）。适配层接管该初始化位置，建立适合 AMPL 授权路径的生命周期。[S2]
3.5 计时
保持 `Runtime`（Gurobi 内部求解时间）以秒读取、乘 1000 后作为毫秒返回的原始口径。保留原有分阶段计时字段。[S2]
在独立测试记录中额外统计：表达式生成、AMPL 传输与编译、求解器模型导入或更新、求解、结果读取、整次规划墙钟时间。墙钟时间是从开始到结束实际经过的时间。
规划器会用实际计算时间调整后续起点。因此接入开销本身可能影响闭环轨迹。性能评估同时报告求解器内部时间和完整规划时间。[S4]
4. 建模适配层的实现边界
建议新增 `include/sando/ampl_model.hpp`（建模适配头文件）和 `src/sando/ampl_model.cpp`（实现文件）。使用项目内部命名空间，必要时在求解器文件内提供局部类型别名，让原始长公式继续编译。
4.1 必须实现的能力
能力	交付内容
变量	类型、上下界、目标线性项、唯一标识、名称、解值
仿射表达式	系数表与常数；变量和常数的加减、数乘、除以标量
二次表达式	仿射表达式相乘，线性项、常数项和交叉项完整展开
普通约束	小于等于、大于等于、等于
二次约束	原版三维长度限制所需二次形式
指示约束	二元变量、触发值、线性约束体
更新与删除	原有对象句柄、代次和批量更新语义
参数	日志、线程数、求解时限，以及源码实际使用的参数
结果与异常	原生状态、目标值、变量值、内部时间、明确错误传播
中止	现有原子标志与求解器回调连接
仿射表达式的意思是“变量乘系数后相加，再加常数”。二次表达式还包含两个变量的乘积。
句柄是程序识别变量或约束的小编号。删除对象后，其旧编号保持失效；重新使用相同显示名称时生成新代次。避免通过当前位置猜测对象身份。
求解器工具头文件也直接包含 Gurobi C++ 头文件，需要一起接入适配层。源码中 `GetNorm2`（平方和）和 `MatrixMultiply`（矩阵乘表达式）保持原有运算语义。[S2]
4.2 两阶段模型生命周期
完整导入阶段。 每个真实 SANDO 问题先通过 AMPL 编译成 NL，再由 AMPLS 导入。该阶段用于建立模型对应关系、验证授权与数学结果。保留常驻 AMPL 会话，临时文件分工作单元隔离。
持久模型阶段。 在完整导入及变量映射验收后，使用 AMPLS 提供的底层 Gurobi C 接口，对同一个真实模型执行原有增删约束、更新目标等操作。该阶段的目的是贴近官方模型复用方式，减少每周期编译和导入开销。[A1][A2]
每次更新都与独立完整导入结果核对。辅助变量、指示约束拆分或名称转换存在时，先完成明确的所有权映射，再启用增量更新。所有模型对象保持由原始 AMPLS 对象管理，借用的原生指针在所有者存活期间使用。
保留原版对模型复用和求解器状态的处理。单独增加上一周期解作为初始化的实验，归入扩展版本。
4.3 AMPL 转换审计
AMPL 编译器和求解器驱动可能进行化简、重排序或约束改写。[A5]
验证版使用 `option presolve 0`（关闭 AMPL 预处理）便于追踪原模型，同时保留原版的 Gurobi 参数。生成变量与约束名称文件；用对应开发包的映射接口恢复变量值。
在 Gurobi 原生模型求解前逐项核对：变量类型与边界、线性约束、二次目标及常数、二次约束、指示约束的触发变量与方向。采用该版本文档支持的转换选项，并保存选项清单。最终验收依赖导出的原生模型，不能只依据设置名称。
公式数值序列化采用足够往返恢复双精度的精度，并保留小系数。独立校验器检查有限数值、尺度和误差。

8.2 数学检查
固定输入应覆盖：四/五/六段、所有已有动力学限幅模式、原有变量消元开关、不同平面数量、空区域、时间分层区域、贴近边界、可行与不可行问题。
独立校验起终点位置/速度/加速度、段间连续性、全部用于建模的动力学控制点、地图边界，以及所选时间层内的全部走廊平面。对于动态场景，检查器与建模器采用同一时间索引。
轨迹采样用于额外发现问题；控制点和解析约束检查承担主要可行性验收。进一步区分“满足预测走廊”与“仿真真值下发生碰撞”两类结果。
误差阈值根据变量单位、系数尺度和实际求解器容差预先确定。简单标准化小问题可用 1e-6 级别误差作为测试起点。目标相对误差、位置/速度/加速度误差和整数容差分别记录。
存在多个最优解时，比较目标值与全部约束；确定性唯一解的小问题再要求变量一致。完全相同的二元选择和逐位一致的浮点结果属于更严格的附加目标。
8.3 场景顺序
保持原版四类模式：[S1][S8]
交互目标：图形界面点目标，验证基本闭环。
静态障碍：低、中、高三档。
已知动态障碍：低、中、高三档。
未知动态障碍：低、中、高三档，包含感知和跟踪链路。
逐场景保存参数、随机种子、障碍轨迹、成功/碰撞/超时、规划次数及时间分布。通过局部轨迹基准和时间分层走廊测试后，再验收全部场景。
建议工程回归最低采用每档十个固定种子；性能统计使用更大样本和重复运行。此数量是本方案建议值，论文复现按论文和配套脚本的实际设置执行。
8.4 性能报告
报告内部求解时间与完整规划时间的中位数、95/99 百分位、最大值和超时率。把初次授权/启动开销与稳定运行阶段分开。
同机严格对照需要同一 SANDO 提交、同一实际输入、同一 Gurobi 版本、同一容差、线程与初始化。存在版本差异或缺少原生参考执行时，报告实测接入版本的结果与已验证的数学等价范围。
正式复现版本采用原来的时间系数调度和求解成功条件。单独优化初始化、接受超时可行解、改变约束表示等实验分别保留版本。
9. 给本地开发助手的执行顺序
读取本文件所列实际源码，固定基准提交和子模块，建立独立开发分支。先报告当前工作树状态，再执行针对性改动。
第一步：在目标 Docker 环境中取得实际 AMPLS 开发包，运行真实 AMPL 模型的 C++ 测试。补齐并发、中止、重复求解和授权持续运行证据。遇到包装或授权错误时保存完整错误和版本，定位该阻断点。
第二步：实现仅覆盖 SANDO 已用接口的建模适配层，先验证表达式与完整模型导入，保留原有大段系数公式。
第三步：运行固定输入的原生模型审计与独立约束检查，再接回原有轨迹提取和状态处理。
第四步：恢复原有并行时间系数工作流，验证停止、清理和下一轮运行；通过后实现并验证持久模型更新。
第五步：修改 Docker 构建上下文、运行时授权与所有相关构建目标，验证镜像实际源码。
第六步：依次执行局部基准、时间分层测试和全部仿真场景，输出逐项验收表。现有版权保留，新增代码采用功能必需内容，实验记录集中保存。
每步报告：执行内容、实际结果、对应证据和下一项操作。成功状态只对应实际通过的验收层级。
