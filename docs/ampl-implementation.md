# SANDO AMPL 改造记录

记录日期：2026-09-07。源码基准：`93b2eed6bb7e300d212372fe20fc8231508162e0`。本报告区分开发容器实测与最终镜像验收，操作步骤见 [运行指南](ampl-runtime.md)。

## 改造结构

```text
原始 SolverGurobi 轨迹公式、约束和并行调度
  → C++ 表达式记录层
  → 完整真实 AMPL 模型 → AMPL 编译生成 NL
  → AMPLS GurobiModel → AMPL 授权的 Gurobi
  → 按稳定变量标识恢复解、状态、时间和原始目标值
```

这不是用一个小 AMPL 模型获取授权后绕过建模；每次实际轨迹问题都完整导出并经 AMPL 编译。

| 范围 | 实际工作 |
| --- | --- |
| 表达式记录 | 新增 `ampl_model.hpp/.cpp`，覆盖连续/整数/二元变量、仿射/二次表达式、线性/二次/指示约束、参数、删除、更新与解值访问。稳定 ID 不依赖数组下标，过期或跨模型句柄报错。 |
| AMPLS 运行 | 新增 `ampls_runtime.cpp`，使用独立临时目录、`posix_spawn` 调用 AMPL、AMPLS 所有权与借用的原生模型指针；支持完整导入和持久模型更新。 |
| 原始代码边界 | 两个求解器头文件按宏切换适配层；调整变量删除接口、模型生命周期与错误诊断。4/5/6 段长公式、时间因子搜索、走廊及动力学约束、成功状态判定均保留。 |
| 构建 | `SANDO_USE_AMPL` 开关连接匹配的 AMPLS/Gurobi 库；公共规划源文件编译为静态库，避免四个可执行目标重复编译；所有包含求解器头文件的目标使用一致的宏定义。 |
| Docker | 新增分阶段 Dockerfile、依赖安装器和运行入口；使用本地源码而非重新克隆远程标签；运行时挂载授权；记录源码提交和校验清单。 |
| 使用入口 | 根目录 Makefile 转发，支持构建、接口测试、自动目标和交互场景；默认持久化模式，Xvfb 支持无显示环境，ROS/Gazebo 隔离参数可配置。 |
| 验证 | 表达式单元测试、真实模型探针、九并发实例、超时/中止恢复、持久化增删与目标更新、18 种轨迹组合、跨授权周期测试以及实际飞行。 |

## 关键问题与解决

| 问题 | 处理方式与证据 |
| --- | --- |
| 普通 Gurobi C++ 环境不能直接代表 AMPL 授权路径 | 使用官方 AMPLS 加载真实 NL，并借用它持有的 Gurobi C 模型；不自行创建替代授权环境。固定 AMPLS 提交与官方配套库包校验值。 |
| AMPL 省略固定/无用变量，并可能重排或增加列 | 按 `v_ID` 映射，恢复被省略变量的原始域；有引用且非固定的变量缺失时明确报错。保留原源码产生的无用二元变量，不修改轨迹公式来规避它。 |
| 约束方向不一致 | 适配常量使用原生字符 `<`、`=`、`>`，避免与 Gurobi 宏混用后把不等式当成等式；用有实际作用的上下界检查方向。 |
| 删除变量、指示约束和表达式的生命周期 | 记录层按原调用顺序处理删除，更新时清理失效指示约束；拒绝过期/跨模型句柄；失败后清除旧解可见性。 |
| 持久模型原生 API 和辅助变量处理 | 使用已存在的 `GRBdelq`/`GRBaddqpterms` 更新二次目标，清理旧行及辅助列，保留变量名称存储寿命，并断言更新后的原生变量数与记录模型一致。 |
| 回调对象失效 | AMPLS 的空回调设置不安全，改用原生回调注销和 RAII，在正常返回、中止及异常退出时清理栈回调。 |
| N6/L2 目标报告差异 | 原生 ObjVal 为 `0.018495181386242621`，返回轨迹代价为 `0.018415185088884799`，记录表达式计算为 `0.018415185061164199`。后两者一致到约 `3e-11`；固定目标辅助变量无漂移。采用原始目标在返回解上的 long-double 累加值，原生值保留于诊断，不放宽严格测试或改变求解容差。 |
| 云授权租约周期 | 每周期正常调用 AMPL 编译，保留其授权刷新路径；七分钟八次求解及同一个持久模型保持六分钟后的更新均通过。 |
| 整包宏定义传播 | 转换节点也包含求解器头文件，只有后端目标携带宏会误找 `gurobi_c++.h`；启用 AMPL 时统一定义，整包编译通过。 |
| Docker 重复发现 Livox 包 | Livox SDK/驱动已分别安装，主工作空间排除重复的 `livox_ros_driver2`、`livox_sdk2`；修正后依赖镜像构建完成。 |
| 最终 Docker 层重复符号链接 | 依赖阶段已创建链接，重复 shell 条件会返回非零；上传前审查删除冗余最终层循环。此修复做了静态与已有依赖镜像检查，最终镜像仍需用户构建确认。 |
| 仿真实例相互发现 | 实测发现域 20 的同名节点和已占用的 Gazebo 11345 端口；默认改为可覆盖的域 42、端口 11346，仅停止本次启动的实例。 |
| 无 DISPLAY | 入口启动 Xvfb 并等待就绪；无界面也能验证自动飞行，鼠标交互仍需可见图形会话。 |

## 已取得的验证结果

- 开发容器整包编译通过，覆盖主规划节点、局部轨迹基准、可视化、时间分层走廊测试和走廊生成节点。
- 最新代码完整导入测试：4/4 通过；持久化加独立完整导入核验的轨迹测试通过。
- 轨迹矩阵：4/5/6 段 × Linf/L1/L2 × 变量消元开/关，共 18 组，检查边界状态、连续性、动力学约束、贝塞尔控制点走廊及加加速度目标，并重复更新；空走廊正确拒绝。
- 持久化探针强制非零交叉项，并激活二次约束，检查替换二元变量、目标常数、约束方向和不可行状态。
- 同一持久模型保持 360 秒后更新与独立核验通过；另有七分钟内八次重复求解通过。
- 开发容器 `static_easy` 完整导入与持久化模式均进入 `GOAL_REACHED`，目标为 `(105,0,2)`。完整导入末端观测约 `(104.88,-0.22,1.87)`；到达判定保留原场景逻辑。
- 新的 `sando-ampl-dependencies` 镜像已经完成构建；其完成不等于最终 `sando-ampl` 镜像完成。

本机日志和模型审计产物位于 `docker/results/ampl-validation/`，不提交到 Git。仓库提交测试源码和结果摘要，授权信息不提交。

## 明确边界

最终 `make build BUILD_JOBS=4` 和基于最终镜像的 `make run-demo SCENARIO=static_easy` 仍需继续执行，不能把开发容器成功等同于最终镜像已验收。动态场景、其他难度与真实机器人没有做新的闭环验收。

持久化模式仍为每次问题调用 AMPL 编译器，没有实现常驻 AMPL 解释器或消除编译成本。测试中编译约 38–39ms；这些数据不是完整飞行性能承诺。配套 Gurobi 实测 13.0.2，原镜像为 11.0.3，不作同版本性能比较。
