## 一、固定最终目标

每次局部规划请求的主链保持：

    当前部署可见观察
      → 共享编码器提取一次共同特征
      → 时间头提出一个T
      → 按这个T构造实际走廊与约束
      → 条件赋值头提出一组完整z
      → 一次固定T、z的硬约束二次规划
      → 原模型残差与时效检查
      → 追加并发布整条局部多段轨迹

沿用0007号架构决策的内部顺序：共享编码器计算一次共同特征；时间头提出时间；走廊生成器按该时间工作；条件赋值头选择完整分配。两个头的内部先后属于一次联合策略计算。主链的完整分配和轨迹计算覆盖全部局部轨迹段。

一次求解指一次主优化调用。求解器为完成这次调用而进行的内部迭代沿用其正常算法。动态未知环境仍按既有周期接收新观察和重规划。

主链预算：一个时间、一组完整赋值、至多一次主二次规划。进入求解且主链成功时，主二次规划次数恰为1。几何或输入提前拒绝的请求，主求解次数可为0，计为主链失败。

安全回退继续保留，并具有独立阶段标识。它的全部时间、求解次数和最终轨迹来源进入记录。回退成功属于系统最终成功；一次性成功只计入主二次规划直接成功且实际通过追加、时效与发布检查的请求。

最终研究目标是提高合法可行输入上的一次性成功率，并缩短完整请求及任务时间。测试集中的主链失败和回退需求必须完整披露。有限测试覆盖的结论，按对应地图、状态、时间范围和硬件解释。

多时间扫描、专家枚举、已知好赋值重放属于离线研究工具；它们的数据和调用次数单独记录。正式主链继续维持单提议预算。

### 3.2 候选上限在“前次赋值”路径有边界缺陷

已核对重放的 `first_candidates`（候选选择函数）和在线 `generateWithCorridorPolicy`（带走廊策略求解函数）：前次赋值先被插入，然后进入枚举循环；循环在追加后才检查数量是否等于上限。

最小反例：上限为1，前次赋值有效且位于枚举末尾。初始列表已经有1项；第一次枚举追加另一个赋值后变成2项，随后等于1的停止条件持续失效。用五段、每段两种选择的控制流复现会得到32个候选。

修复原则：循环进入及追加前都保证剩余容量，统一去重并保证返回数量小于等于上限。覆盖前次赋值位于首、中、末位置，前次赋值缺失或无效，以及上限1和3。在线与离线行为一致。

该问题针对前次赋值分支。现有模仿和代价监督分支的60实例数字，按各自代码与原始尝试数独立核验。

同时检查候选上限的命令行与环境变量输入：仅接受有效正整数，负号、尾随字符、溢出和零都进入明确参数错误；保持命令行与环境变量优先级一致。

### 3.3 求解器重建后保持单候选配置

### 3.4 当前重放测量属于每实例每方法新建求解环境

重放主循环对每个输入实例和每个方法调用 `createRuntime`（创建求解环境函数）；同方法的主尝试与回退共享这个环境。元数据也记录了每方法新环境。

### 3.6 当前计时边界的语义

保留 `total_ms`（既有重规划总耗时）的历史定义。新增字段按事件是否发生给值，缺失用空值与原因表达。

- `usable_ms`（目前记录首个成功求解结果的边界）发生在追加计划前；随后可能出现追加过期。把“求解结果就绪”和“轨迹可执行并被采用”分别记录。
- `reclaim_ms`（资源回收完成累计耗时）保留累计定义，取消等待本身继续使用独立跨度。
- `publish_ms`（现有自身轨迹分享发布累计耗时）由 `publishOwnTraj`（发布自身轨迹函数）产生，所对应的是 `/trajs`（轨迹分享话题）。控制目标经另一条发布路径送出，执行端首次使用新计划的时间另加独立观测。
- 首个结果未出现、局部规划未进入、追加失败、发布未出现分别有明确状态。旧记录的0值按旧语义兼容读取。

每条事件携带运行、请求、轨迹版本和尝试身份。发布时间采用进程单调时钟的累计值；运动与碰撞使用仿真时间；保存二者的配对观测。回调并行时保护记录，避免读到后一请求的编号或旧结果。

同时记录两种量：决定用户等待多久的真实关键路径；各尝试累计工作量。阶段累计墙钟与实际处理器时间分开命名。并行分段按请求内实际重叠关系分析，百分位在完整请求耗时上计算。

### 4.4 静态森林几何可以部分解除阻塞

从对应版本的世界文件解析静态树的实际碰撞形状、全局位置、半径、高度和方向，并核对里程计坐标系及机器人所用几何。

静态树的位置恒定。对已有里程计位置序列，可逐样本计算相交；这个任务只需要每个机器人位置与同坐标系静态树形状。旧首次包围盒事件的精确时间对齐属于另一项验收，继续保留其缺口。

当树为竖直圆柱、机器人使用轴对齐盒代理时，记树中心为c，半径r，高度H；机器人中心为p，半尺寸为hx、hy、hz：

    dx = max(abs(px-cx)-hx, 0)
    dy = max(abs(py-cy)-hy, 0)
    平面相交：dx² + dy² ≤ r²
    高度相交：abs(pz-cz) ≤ hz + H/2

两项同时成立，表示这一代理几何在该采样位置相交。先核验世界中的圆柱方向、局部位姿组合、盒尺寸和坐标系，再使用此公式。机器人姿态、真实网格和连续时间安全各自需要相应模型及证据。

新采集同时保存仿真时刻、机器人位姿、动态障碍位姿、碰撞几何身份，优先使用原碰撞检测回调同一条消息。动态场景按同采样时刻复算。静态逐样本检查、原首次事件复算、全时段连续碰撞检查分别汇报。

### 5.2 真正的新时间查询

当前 `scripts/reconstructable_request.py`（请求整理与时间查询脚本）的同时间分支复制原结果，新时间字段完整分支只返回时间计算状态。下一接口需要实际构建走廊并调用求解器。

输入：冻结请求、目标时间因子、参考求解或指定完整赋值、固定预算。
输出：观察身份、时间与层边界、真实几何身份、完整赋值、原模型身份、求解状态、原目标、恢复轨迹、原问题残差、全部尝试与墙钟。

实现复用当前C++（编程语言）在线几何和问题构造函数。第二部分通过接口消费同一实现。固定时间旧数值矩阵只复验原时间条件。

验收顺序：新快照在原时间实际重建与求解；核对目标、原约束和恢复轨迹；再查询1.37及预定时间网格。几何不变的静态实例允许走廊相同，时间相关轨迹矩阵与实际层时刻仍须正确。

小表脚本现有“1.37必须阻塞”检查限定为旧缺失快照回归用例；新完整快照按真实求解状态验收。输出目录采用新轮次，原表保持只读。

### 5.3 模型交接

交接分三个层次：

1. 固定输出或兼容单输出模型：验证接线和协议。
2. 当前可训练得到的独立时间模型加走廊模型：验证独立组合方案。
3. 共享编码器与条件双头的新训练模型：验证最终主结构。

每份模型附：真实文件、内容哈希、模型格式、输入语义及顺序、时间范围、段数、归一化、父模型身份、训练数据与种子、验证选择、在线一致性结果。完整模型文件和一致性测试记录共同构成可运行交付。

第一份模型交付即可解锁对应工程检查。第三份模型的性能结论继续以真实训练和独立评测为前提。

## 六、阶段7：四组主预算对照

原多时间系统单列为历史预算参照。四组局部对照固定一个主时间：

| 组别 | 主时间 | 完整赋值 | 主求解 |
| --- | --- | --- | --- |
| 固定时间参考 | 固定f0 | 原整数求解器选择 | 一次混合整数问题 |
| 只学时间 | 网络给出f | 原整数求解器选择 | 一次混合整数问题 |
| 只学分配 | 固定f0 | 网络完整分配 | 一次固定赋值二次规划 |
| 联合模型 | 网络给出f | 网络完整分配 | 一次固定赋值二次规划 |

原整数参考的内部搜索工作是其算法成本，完整记录。学习主链保留一次主二次规划。

固定f0可沿用现有协议2.0，但必须核对所有基线实例的实际因子和模型约束。原捕获因子不同的实例，使用真实观察重建到2.0后才进入该固定时间对照。仅修改时间元数据的记录保留为无效输入诊断。按各自原时间重放的结果命名为“原捕获时间对照”。

回退规范在试验前按实际代码冻结：主二次规划后的同时间混合整数求解、后续原时间搜索、旧计划处理分别登记。原模型约束和原安全处理保持一致。若架构决策要求的外层回退尚未接通，先记录实现差距，并完成相应共同流程测试。

每组均报告主尝试指标和包含全部回退的系统指标。对额外调用的判断以真实求解入口计数为准。

正式比较共同冻结源码、镜像实际二进制、线程、处理器集合、时间与观察上限、求解接受条件、安全参数、控制器、记录级别、地图和种子。更改配置形成新身份，旧记录保留。

一次性效率用全部请求的主链成功率与实际发布延迟共同判断。成功样本的单独延迟作为补充；失败、未决、超时的代价按预登记共同规则计入系统指标。

先完成现有两组的新在线预检，待各层模型交付后补齐对应两组。最后使用全新冻结场景完成主结构试验，旧开发集继续承担回归职责。

## 七、阶段8：围绕一次性失败补数据

将已确认的失败状态交给第一部分查询器：主时间不可行、当前时间可行但赋值错误、数值异常、候选通过而追加过期、场景信息缺失分别编号。

离线补表使用同一冻结观察扫描多个时间；每个时间重建几何。完整枚举与有限预算参考分开；未决结果原样保留。新飞行产生的新观察归入新数据轮次。

训练目标应支持主提议直接成功：既记录原轨迹目标与时长，也记录主候选可行性、原约束裕量、失败类型。第一部分负责损失与训练；第二部分只提供证据和冻结评价。

同状态多时间标签按请求归组，训练/验证/测试继续隔离。学习观察保持部署可得；真值仅用于独立几何和任务评价。

新模型到达后，先用冻结同状态输入比较首提议通过率、代价与耗时；再用独立飞行评价到达、碰撞代理、完整任务时间和回退需求。数据增加带来的收益与模型结构变化分别对照。
